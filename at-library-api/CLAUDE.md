# at-library-api — заметки для быстрой работы

Дополняет [../CLAUDE.md](../CLAUDE.md) и [README.md](README.md) (там подробно описаны типы параметров таблиц, `application.properties`, JSON-шаблоны тел запроса, список публичных API для тестов). README уже отдельно объясняет каталог `feature-extensions/` (заготовки, специально не подключённые в постоянный прогон) — не путать с обычным `features/`.

## Тестовые раннеры

Тот же паттерн, что в `at-library-web` (см. [../at-library-web/CLAUDE.md](../at-library-web/CLAUDE.md)) — несколько раннеров, не только `RunFeaturesTest`:

| Класс | Теги/scope | Назначение |
|---|---|---|
| `RunFeaturesTest` | **без фильтра тегов** | `src/test/resources/features/` — сквозные сценарии на **живых** публичных API: Petstore и httpbin (нужен интернет; данные общие и могут меняться). Используют **только шаги библиотеки** (без тестовых шагов), поэтому файлы можно копировать как примеры. httpbin возвращает в ответе то, что получил, — по нему видно, что параметр таблицы реально дошёл до сервера |
| `RunApiOfflineStepsTest` | без фильтра, `parallel=false` | `src/test/resources/offline/` — **оффлайн-контракт всех шагов**: положительные и отрицательные сценарии без интернета (см. ниже). Основной набор для отладки шагов |
| `RunApiLocalStepContractTest` | без фильтра | `local-contract/api_response_steps_local_contract.feature` |
| `RunApiStepCatalogTest` | `dryRun=true` | regex-контракт по `src/test/resources/step-catalog/api_steps_catalog.feature` |
| `ApiStepCoverageTest` | обычный TestNG-тест | **мета-тест**: падает, если у публичного шага (`@И` в `ru.at.library.api.steps`) нет ни одной настоящей строки шага в `features/`, `local-contract/` или `offline/`. Добавили шаг — добавьте сценарий |

`-Dcucumber.options=...` не работает (см. корневой CLAUDE.md); фильтры — `-Dcucumber.filter.name=...` / `-Dcucumber.filter.tags=...`.

**Запуск одного класса — только по полному имени.** `-Dtest=RunFeaturesTest` совпадёт и с одноимённым классом из `at-library-core`, а тот стабильно падает (Groovy/AspectJ vs новая JDK) и останавливает реактор до `at-library-api`:
```bash
mvn -o -pl at-library-api -am test -Dtest='ru.at.library.api.RunApiOfflineStepsTest,ru.at.library.api.ApiStepCoverageTest' \
  -Dsurefire.failIfNoSpecifiedTests=false -Dapi.http.log.disable=true
```
Раннеры с суффиксом `*IT` не входят в обычный `mvn test` (действует конвенция failsafe) — поэтому такие раннеры здесь убраны: всё лежит в `*Test`.

## Оффлайн-набор (`offline/`)

- **Ответы для response-шагов** строятся в памяти: `Дано подготовлен локальный (JSON|XML|YAML)-ответ "r":` + DocString (`LocalApiContractSteps`); тело дополнительно доступно как переменная `r_body`.
- **Request-шаги** работают с локальным сервером: `Дано запущен локальный HTTP сервер` (и `... HTTPS сервер с самоподписанным сертификатом`, сертификат создаёт `keytool`). Адреса публикуются в переменные `local_echo`, `local_status`, `local_flaky`, `local_poll`, `local_cookies`, `local_headers`, `local_basic`, `local_bearer` … (полный список — `LocalHttpServerSteps#publish`; для HTTPS префикс `local_https_`). `/echo` возвращает JSON с тем, что получил сервер (метод, query, headers, cookies, form, multipart, body) — так проверяется, что таблица запроса реально дошла до сервера.
- **Отрицательные проверки** — один универсальный шаг: `Тогда выполнение шага завершается ошибкой, содержащей "фрагмент":` + DocString с текстом настоящего шага (и таблицей строками `| a | b |`). Шаг ищется по regex реальных аннотаций и вызывается рефлексией (`ApiStepRegistry`, `ExpectedFailureSteps`), поэтому сценарий заодно проверяет формулировку шага. Сообщение сравнивается с цепочкой «класс: сообщение ← причина…».

Подводные камни, на которые уже наступили:
- Regex значений в шагах — `"([^"]+)"`: **двойную кавычку внутри значения передать нельзя** (и пустую строку `""` тоже). JSON с кавычками сравнивайте через `body ответа … сохранено в переменную` + `в JSON строке "{var}" значения соответствуют таблице:`.
- Пустая ячейка таблицы Cucumber приходит как `null` (`| BODY | | значение |`) — шаги должны это переживать (`SendRequestSteps.resolveCell`).
- Значение ячейки таблицы запроса подменяется **содержимым файла**, если это существующий файл/ресурс. Для `FILE` нужен именно путь, поэтому там используется исходное значение ячейки.
- Шаги со строковыми переменными принимают их в фигурных скобках: `"{json_str}"`.
- Шаг `заполнение (JSON|XML)-шаблон …` всегда требует таблицу; плейсхолдеры в ней — regex (`\{\{orderId\}\}`), значения подставляются через `replaceAll` (значения с `$`/`\` пока обрабатываются некорректно — осознанно не исправлено).
- `ProxySteps` меняют глобальные системные свойства и `RestAssured.proxy`, поэтому оффлайн-раннер последовательный, а сценарии proxy помечены `@local-api-proxy` (хук очищает состояние).
- Тестовые шаги (`LocalHttpServerSteps`, `ExpectedFailureSteps`, `LocalApiContractSteps`, `ApiStepRegistry`) лежат в `src/test/java` и **не попадают в jar** (проверено по содержимому `at-library-api-*.jar`, `-all.jar` и итогового `distribution/.../at-library-*.jar`). Из main в сборку добавлен только вспомогательный класс `helpers/ArrayValues`; новых `@И`-шагов в библиотеке нет.
- Усиленные проверки в `features/` должны падать, если шаг проигнорировал параметр: перед правкой сравнивайте с оригиналом (`git checkout HEAD -- <шаги>` + прогон) — так видно, что тест действительно ловит дефект. Пример: массив из одинаковых `status` проходит проверку сортировки в обе стороны, поэтому для сортировки данные задаются явно через echo httpbin.
- `FILE`: работает путь напрямую, имя property, а также `{переменная}` / `{property}` в фигурных скобках (так шаг работал и раньше). Голое имя переменной без скобок не подставляется. Имя колонки — MIME-тип, имя multipart-поля всегда `file`.
- `BASIC_AUTHENTICATION` отправляет логин и пароль сразу (preemptive), а не после `401` с `WWW-Authenticate`: на `httpbin.org/hidden-basic-auth` (отвечает 404 без учётных данных) иначе не пройти.
- Массивы: числа и boolean сравниваются как строки (`"2"`, `"true"`), сортировка числовых массивов — числовая; массив объектов со строкой не сравнивается (нужен путь до скалярного поля, например `items.name`); `не пустой` отклоняет `null`, отсутствие поля, не-массив и `[]`.
